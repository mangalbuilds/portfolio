Prex — Startup Job Discovery

Automated Scraping & Filtered Alerts for Early-Career Roles

A job discovery web platform and scraping pipeline built to find early-career roles (AI PM, Growth, and Founder's Office). Runs scheduled searches across company career pages and ATS platforms, filters listings by experience level, logs qualified roles to a database, and posts updates to Telegram.

Web App n8n Automation Playwright E2E Serper API Telegram Alerts Supabase / SQLite Razorpay Checkout

01. WHY I BUILT IT

Searching manually through dozens of startup job boards and ATS pages every day was tedious. I built Prex to automate role discovery and aggregate junior-friendly listings in one place.

02. SYSTEM ARCHITECTURE

  • Automated Scraping: Scheduled queries search for fresh openings on ATS platforms such as Ashby, Greenhouse, and Lever.
  • Rule & LLM Filtering: Filters out senior and lead titles to focus strictly on entry-level and 0–2 years experience roles.
  • Notification & Storage: Sends qualified matches to a private Telegram channel and logs job metadata into a Supabase database.
  • Web Interface: Built a web frontend allowing visitors to browse listings, with a Razorpay checkout for optional pro access.
  • Automated E2E Testing: Wrote Playwright test suites for local and live production to verify search filters, candidate profile flows, and checkout modals before releases.

03. CURRENT STATUS

● Live Project: Web interface accessible at getprex.com. Code and automation workflows stored on GitHub.

WORKING PROTOTYPE ughar.in

UGhar — Hyperlocal Home Services Prototype

Technician Booking & Dispatch Prototype • Jamshedpur

A functional prototype for booking home repair services in Jamshedpur. Built end-to-end user flows including service selection, OTP verification, and dispatch confirmation, exploring a transparent flat inspection fee model through local field research.

Web Prototype Next.js Supabase Firebase Auth Field Research

01. PROBLEM & FIELD FINDINGS

Household repairs in Tier-2/3 cities often face fragmented pricing and inconsistent service. Local interviews with residents across Jamshedpur showed strong preference for a upfront, low inspection fee that gets adjusted into final repair costs.

02. USER FLOW

Phone OTP Login → Service Selection (AC, Plumbing, Electrical) → Address Input → 4-Digit OTP Confirmation on Dispatch.

03. TESTING & EDGE CASES

  • Boundary Validation: Tested form inputs against extreme values, empty fields, and invalid phone numbers.
  • OTP Expiry: Verified edge cases during network slowdowns and unverified resend attempts.
  • Mobile Viewports: Tested layout responsiveness across multiple smartphone screen sizes.

04. CURRENT STATUS

● Functional Prototype — Core flow built and tested locally; live as a portfolio demonstration.
